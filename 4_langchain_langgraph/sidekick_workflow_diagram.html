Architecture diagram

The Sidekick worker/evaluator loop

One call to run_turn() and everything that can happen inside it: the worker streams, an independent evaluator grades the result against the user's success criteria, and two separate paths can suspend the loop — a human-approval pause and an automatic retry.

4_langchain_langgraph/sidekick.py

What each step does

1

run_turn(message, success_criteria)

Entry point for a new user turn. Wraps the success criteria into the first user message, resets attempts and todos, and hands off to _advance().

2

Worker.astream(...)

The create_agent graph streams its state. TodoListMiddleware tracks the plan shown to the UI; both PIIMiddleware instances redact emails and card numbers; ModelCallLimitMiddleware caps the run at 30 model calls; TolerateToolErrors turns a failing tool call into a message instead of a crash. InMemorySaver checkpoints everything under this Sidekick's thread_id.

3

interrupted?

After the stream ends, _advance() checks the result for __interrupt__ — raised by HumanInTheLoopMiddleware just before send_push_notification or request_human_help would actually run.

If interrupted — the approval side path
A

Paused

The pending action count is stored, self.paused = True, and a "waiting for your approval" message returns to the caller immediately — the turn stops here rather than continuing.

B

resume()

Once the user approves, resume() sends Command(resume={"decisions": [...]}) with one {"type": "approve"} per pending action, and _advance() re-enters the same astream loop.

If not interrupted — the evaluation path
4

Evaluator judges

A second, smaller LLM call — not the worker — scores the reply against the success criteria, using the ordered list of tools actually called as evidence rather than trusting the worker's self-report.

5

done?

The loop exits when the evaluator marks the criteria met, or the worker itself needs user input, or three attempts have been used — whichever comes first.

6

retry payload

Otherwise the evaluator's feedback is wrapped into a new user message and the worker tries again in the same thread, with attempts incremented.

7

Return to caller

The worker's final reply and the evaluator's feedback are both appended to the conversation history and handed back — run_turn() or resume() returns this list straight to the user.
